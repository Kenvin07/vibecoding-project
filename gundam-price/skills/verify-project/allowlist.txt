# 【这个文件解决什么问题】
#   Day 23 的自查清单里，为了让读者看懂"什么算密钥真值"、以及"怎么证明扫描脚本
#   不是永远返回 0 的摆设"，故意写了两个**假值示例**：
#       1) 行文举例：一个键名 + 等号 + 引号里三个点收尾的省略写法；
#       2) 自测命令：用 printf 造一条含 deadbeef 假值的赋值语句到临时文件。
#   这两个是**文档里的教具**，不是泄漏。但扫描器的判据是"键名 + 引号里的长串"，
#   分不出教具和真值 —— 于是每次发布前检查都会报 2 条假警。
#
# 【为什么用白名单，而不是把文档改掉】
#   改掉示例，Day 23 那份文档的"灵敏度自测"就失效了（读者照着跑，脚本却抓不到）。
#   白名单是更诚实的做法：**误报不隐藏，但豁免要留痕**。检查结果里会显示
#   "原始命中 N 条，白名单豁免 M 条"，不是悄悄变成 0。
#
# 【维护规矩（必须守）】
#   ① 只允许加「文档/注释里的示例值」，一条一行，用 grep -E 正则写；
#   ② 每条前面用 # 写清：来自哪个文件、为什么是示例；
#   ③ 绝不允许为了让检查变绿而把真值加进来 —— 真值只有一个去处：云函数环境变量；
#   ④ 白名单变长 = 有人反复用假密钥举例，回头应该改文档写法（用 <占位> 代替引号长串）。
#
# 【本文件自己也踩过的坑】
#   最初这里把示例写成完整形态（键名 + 等号 + 引号长串），结果扫描器扫到本文件，
#   对着白名单自己报警。所以下面只写「值」的片段，不写完整赋值形态 ——
#   凡是"扫描工具"，都要先把自己摘出去。
# ===========================================================================
