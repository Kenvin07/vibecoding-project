### 版本号怎么读

`主版本.次版本.修订`：

- **主版本**：对外宣布「这个东西能用了」才进一位 —— 今天是第一次，所以 1.0.0
- **次版本**：加功能进一位（如 1.1.0 新增价格提醒）
- **修订**：只修 Bug 进一位（如 1.0.1 修文案）

**回滚的目标版本号永远写成完整三段**（`0.9.0`，不是 `0.9`），否则脚本与 `version.json` 对不上。

### 版本标记怎么落到线上

版本号只写在一个地方：`version.json`，由发布脚本在打包时生成。

```
gundam-price/releases/v1.0.0/version.json   ← 唯一真值，跟着包一起上传
           ↓ 页面加载时由 js/version.js 读取
           页脚显示「v1.0.0 · 2026-10-19 · 正式版」
```

所以页脚那行不是装饰，是**线上版本的读数**：发布后它变 1.0.0 = 传对了；回退后它消失或变 0.9.0 = 退对了。

## 五、代码与数据备份方式

### 5.1 代码：三层备份

| 层 | 是什么 | 怎么恢复 | 失效场景 |
|---|---|---|---|
| ① Git 提交 | 每次改动的完整历史 | `git checkout <提交>` | 本地仓库所在磁盘损坏 |
| ② 远端仓库 | GitHub `Kenvin07/vibecoding-project` | `git clone` | GitHub 不可用（极少） |
| ③ 版本标签 | `v1.0.0` 指向发布的那一次提交 | `git checkout v1.0.0` | 同上 |
| ④ 发布包 | `releases/v1.0.0/` + zip（不进 Git，可重建） | 见下 | 本机磁盘损坏（可用脚本重建） |

发布包不进 Git 的理由与重建方法：见 `gundam-price/releases/README.md`。核心是一句话：

```bash
# 任何时候、任何一台有仓库的机器，都能把某个版本的包重新做出来
bash gundam-price/scripts/make-release.sh 0.9.0 efa8050
bash gundam-price/scripts/make-release.sh 1.0.0
```

**「版本号 + 提交号」就是发布包的配方** —— 这比把 zip 提交进仓库更可靠，也不会让仓库变成仓库 + 网盘。

### 5.2 数据：四个层次，从轻到重

| 层次 | 备份什么 | 怎么做 | 恢复粒度 |
|---|---|---|---|
| ① 结构 | 两张表的建表语句 | `db/schema.sql` 已在 Git 里 | 整库重建 |
| ② 录入源 | 每天的最低价格与历史价 | `data/data.json` 在 Git 里，每次改价都提交 | 按天回看 |
| ③ 业务数据 | `kits` / `kit_prices` / `checkins` 的实际行 | 改动前先 `SELECT` 导出成 SQL 文件存本地（命令见下方） | 按表 / 按行 |
| ④ 兜底 | 被误删的记录 | 软删除：`isDeleted = true`，数据还在表里，改回 `false` 即恢复 | 单条 |

改数据前留一份现场（把 `<日期>` 换成当天）：

```sql
-- 1) 导出当前数据（结果复制保存到 gundam-price/data/backup-<日期>.sql）
SELECT * FROM kits;
SELECT * FROM kit_prices;
SELECT * FROM checkins WHERE "isDeleted" = false;

-- 2) 误删恢复（把被软删的记录捞回来）
UPDATE checkins SET "isDeleted" = false WHERE id = '<记录 id>';
```

> 数据库**没有「一键回滚」**。真出事的顺序永远是：先确认影响面 → 前端能退就退（秒级）→ 数据问题走上面的导出回灌。这也是回滚手册把「数据恢复」单列成备查项、而不放进 3 分钟流程的原因。

### 5.3 只存在控制台、Git 里没有的配置（重建环境必查）

| 配置 | 在哪 | 丢了会怎样 | 本次是否核对 |
|---|---|---|---|
| `/api` 前缀兜底路由 | HTTP 访问服务 | 未登记路径返回网关 `INVALID_PATH`，前端 404 被误报成网络故障 | 是（N3 PASS） |
| 跨域白名单 | 静态托管侧「跨域设置」 | 页面能开但数据全部加载失败 | 是（N4 PASS） |
| 云函数环境变量（4 个） | 云函数 `api` 的配置 | 云函数报 `ConfigError`，所有接口 500 | 是（S7 PASS） |
| 写接口密钥 | 云函数环境变量 | 写接口全 401（读不受影响） | 是（N5 PASS） |

> 这四项每次换环境、每次大版本发布都跑一遍 `verify-project.sh` 就能自动核对，不需要凭记忆。
