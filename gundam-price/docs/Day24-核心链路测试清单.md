## 三、原因排序（按"最可能是它"的顺序）

> 排序依据不是猜，是**这几条客观事实**：① 契约第 6 节「待定项 13」自己登记了「`POST /api/checkins` 只做了桩自检、真机未单独写入验证」；② 前端没有新增打卡的 UI 与封装，今天才是这条请求第一次真发；③ 读接口（GET）与改/删（PATCH/DELETE）在 Day 22 都做过真机验证。

| 排序 | 嫌疑原因 | 概率 | 为什么排在这个位置 | 一句话判据（能证伪） |
|---|---|---|---|---|
| **1** | **写路径未验证过**：`POST /api/checkins` 从未真机写入过 | 高 | 唯一"纸面通过、真机空白"的一条；写入涉及 8 个步骤、两道防线，最容易在真机暴露 | C3 的 HTTP 状态码是多少？201 以外的每一个码都指向一个具体环节 |
| **2** | **密钥这一层**：`X-API-KEY` 没带 / 值与 `WRITE_API_KEY` 不一致 | 中高 | 私钥只在云函数环境变量里，手抄一次就可能差一个字符；且③ 区块的"只验密钥"结果能直接证明 | 用 ③ 区块的「只验密钥」：`400` = 钥匙对；`401` = 钥匙错 |
| **3** | **跨域 / 安全来源**：前端域名不在白名单 | 中 | 前端（localhost 或静态托管域名）与后端是两个域名，Day 15 起就靠白名单；白名单一被改动就整片红 | Console 里是否出现 `CORS` / `blocked by CORS policy` 字样？请求是否根本没到后端（云函数日志无记录） |
| **4** | **本机模式判断**：④ 区块整块没渲染出来 | 中 | `isLocal()` 只认 `localhost` / `127.0.0.1` / `[::1]` / 空；用别的方式打开页面就整块隐藏 | ④ 标题右侧是「仅本机」还是「公网已隐藏」 |
| **5** | **缓存**：浏览器用的是旧版 `check.js` / `api.js` | 中低 | 脚本靠 `?v=日期` 破缓存，改了 js 但没升版本号就会拿到旧的 | `Ctrl+Shift+R` 后现象是否变化？Network 里 `check.js` 的 `v=` 参数是不是最新的 |
| **6** | **数据层约束**：撞上唯一索引 / 外键 | 中低 | 两道防线都在，正常路径走不到；一旦走到说明前置校验漏了 | 错误原文里有没有 `23505` / `23503` / `checkins_unique_active_day` / `foreign key` |
| **7** | **环境**：本地服务器没开 / 云函数挂了 | 低 | 这一层最容易被误当成 Bug | ① 健康检查是绿的还是红的？红 = 环境问题，与业务代码无关 |

## 四、每个原因的验证方法（一条动作就能证伪）

| # | 验证动作 | 判读 |
|---|---|---|
| 1 | 看 C3 那条请求的 Console 输出：`HTTP ___` 和响应体原文 | 201 → 写通了；401 → 原因 2；400 → 字段/值不对（按 C3 对照表逐条对）；404 → `kitId` 拼错；405 → 请求方法写错（比如写成了 `PUT` 之外的笔误）；500 → 去云函数日志看 `[api]` 开头的行 |
| 1b | 云函数日志（CloudBase 控制台 → 云函数 → `api` → 日志）搜 `POST /api/checkins` | 有「写入成功 id=…」= 后端写库成功了（那问题在前端）；有「被拒：401/400/…」= 后端拦下了（那问题在请求本身）；什么都没有 = 请求没到后端（回到原因 3） |
| 2 | ③ 区块输入密钥 → 点「只验密钥（不写数据）」 | 绿色「密钥有效…400 INVALID_PARAM」= 钥匙对；红色「密钥不对（401）」= 回云函数环境变量逐字符核对 `WRITE_API_KEY`（注意首尾空格、是否粘到了引号） |
| 3 | Console 里手动发一条 GET 到后端：`fetch(BASE + "/api/checkins").then(r=>r.json()).then(console.log)` | 能打出对象 = 跨域没问题（原因 3 排除）；报 `Failed to fetch` 且 Console 有 CORS 红字 = 白名单问题 → 控制台「环境配置 → 跨域设置」把当前页面的来源加进去 |
| 4 | 看 ④ 标题右侧标签 | 「仅本机」= 判断正确（原因 4 排除）；「公网已隐藏」= 你打开页面的地址不对，回 0.4 第 4 点 |
| 5 | `Ctrl+Shift+R`；再看 Console → Network 里 `check.js?v=` 的值 | 强刷后好转 = 缓存；`v=` 与 `check.html` 里写的一致 = 没拿旧文件 |
| 6 | 看错误原文里是否出现数据库约束码；或去 SQL 编辑器执行：`SELECT "kitId","checkinDate","isDeleted" FROM public.checkins WHERE "kitId"='mg-sazabi-verka';` | 能看到别人写过的同机体记录 = 撞了防重复（换日期）；看到 `23505`/`23503` 字样 = 数据库约束在兜底，说明前置校验漏了 |
| 7 | 刷新页面看 ① 健康检查 | 红 = 环境（云函数没起来）；绿 = 环境正常，继续查上面 |

> **一条重要的排除顺序**：先看 **① 健康检查**（环境）→ 再看 **② 两张核心表**（读+跨域）→ 最后才是 **④ 打卡**（业务写路径）。这三步能把"环境/网络/跨域"三大类一次性排除掉，剩下的才是真正要修的代码问题。这就是"怎么排除掉其他原因、锁定真正原因"的方法本身。
