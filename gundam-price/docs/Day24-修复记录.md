# Day 24 修复记录 ｜ 未登记路径的误导提示（跨域被拦）

> 日期：2026-10-15（第 4 周 · Day 24）
> 结论：**零代码改动的修复** —— 只在 CloudBase 控制台新增一条 `/api` 前缀路由。
> ⚠️ 这条路由**不在 Git 里**，重建环境时必须重配，否则本 Bug 原样复发（见第 6 节）。

---

## 1. 现象

| | 内容 |
|---|---|
| 用户视角 | 请求一个未登记（或漏部署）的接口路径时，页面提示「**连不上服务器，请检查网络后重试**」 |
| 真实情况 | 服务器活得好好的，只是那个路径没有登记，后端回了 404 |
| 为什么是 Bug | 明明是「接口不存在」，却让用户去查网络。以后接口改名或漏部署时，会被这条假信息带偏，白查半天 |

复现命令（`check.html` 的 F12 控制台里执行，只读、不写任何数据）：

```js
API.get("/api/nope").catch(function (e) {
  console.log("① HTTP " + e.status + " code=" + e.code);
  console.log("② " + API.humanMessage(e));
});
```

---

## 2. 真因

云开发的**网关**对「没有登记过的路径」直接回 404，**且这份 404 不带 `Access-Control-Allow-Origin`（跨域许可）头**。

浏览器按跨域安全规定**拒收**这份响应 → `fetch` 只能抛 `TypeError: Failed to fetch` → 前端把它当成网络故障。

完整链条：

```
网关 404（缺跨域头）
  → 浏览器拒收（被 CORS policy 拦下，页面读不到响应体）
  → js/api.js:102        挂上 status=0 / NETWORK_ERROR
  → js/error-message.js:40  按 status=0 归为 NETWORK 类
  → js/error-message.js:28  文案「连不上服务器，请检查网络后重试」
```

**前端最后一环没错**——它拿不到真话，只能这么判。错在前端之外。

---

## 3. 定位：四个候选，逐一排除

| 候选原因 | 判据 | 结论 |
|---|---|---|
| ① 网络真的断了 | 同一个页面，其他区块的数据刚刚成功读回来 | 排除 |
| ② 跨域白名单没放行 `localhost:8000` | 已登记路径（`/api/kits`、`/api/checkins`）全部正常返回 | 排除 |
| ③ 后端挂了 / 没响应 | 控制台网络面板里有 `GET …/api/nope 404 (Not Found)`，后端回话了 | 排除 |
| ④ 后端返回的外壳格式不兼容（最初的假设） | **决定性判据：`status = 0`** | **排除** |

**决定性那一刀**：在 `js/api.js` 里，`status` 只有一个地方会变成 `0` —— 第 102 行（`fetch` 抛异常的分支）。
如果真因是「外壳格式不对」，代码会走到第 118 行，并带着后端给的真实状态码 **404**。
实测拿到的是 **0** → 假设④出局，那份 404 响应**根本没送进网页**。

三处交叉佐证：

1. 同一个路径，用命令行（curl）能拿到后端原话 `{"code":"INVALID_PATH",...}` —— 命令行不受跨域管，浏览器受管。两边一对比，真因锁定在「跨域」这一层。
2. 云函数代码里 grep 不到 `INVALID_PATH` —— 这层不是本项目的代码，是网关自己给的。
3. 项目内没有任何路由配置文件 —— 路由是在控制台「HTTP 访问服务」里逐条手配的。

---

## 4. 修复动作（没有改任何代码）

云函数里**本来就写好了**兜底分支（`cloudfunctions/api/index.js` 第 99–101 行）：

```js
if (route === null) {
  return sendFail(res, 404, 'NOT_FOUND', '接口不存在：' + url.pathname);
}
```

问题只在于：请求**压根进不了函数**，在网关门口就被退回了。所以修复＝**在门口打开一条路**：

在 CloudBase 控制台（环境 `gundam-market-d7gnjqg3h1f2f156f`）的「HTTP 访问服务 / 路由管理」里**新增**一条路由：

| 配置项 | 值 |
|---|---|
| 关联资源 | 云函数 **`api`** |
| 触发路径 | **`/api`** |
| 路径透传 | **开** ← 关键项 |
| 域名 | 环境默认域名（**不是** `*`） |
| 身份认证 | 关（与现有路由保持一致） |

**为什么加 `/api` 不会打挂现有接口**：网关路由是**前缀匹配**，且**最长者优先**。
`/api/health`、`/api/kits`、`/api/prices`、`/api/checkins` 都比 `/api` 更长、更精确，永远优先命中；
只有「没有任何精确路由能接」的路径（例如 `/api/nope`）才会落到这条兜底上。

本次**未删除、未修改**任何既有路由。

> 路径透传＝开的佐证：修复后提示里显示的路径是 `/api/nope`（带 `/nope`），
> 说明函数收到的是完整原始路径，而不是被截短的 `/api`。
