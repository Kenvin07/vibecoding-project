**卡点位置**：`check.html` 的 ③ 写入测试 / ④ 打卡记录 两块，在公网域名下被 `isLocal()` 整段关闭。
**试用者视角**：打开公网链接后，页面上**没有任何一个能真正写数据或改删数据的入口**，只有一段「公网已隐藏 / 只在 localhost 下开启」的解释——说了「不能」，没说「那该怎么办」。外行只能自己到处乱点，最后反馈「都挺顺」这种**假阳性**。

## 二、根因

`js/check.js`：

- `isLocal()` 只认 `localhost` / `127.0.0.1` / `[::1]` / 空字符串（第 51–54 行）。
- `renderWrite()`（第 165 行起）、`renderEditBox()`（第 446 行起）在 `!isLocal()` 时直接 `return`，只渲染一句说明。
- `loadCheckins()` 只在 `isLocal()` 时被调用（第 647 行）。

这个设计本身是**对的、必须保留**：写接口要带 `X-API-KEY`，密钥不能进前端代码。所以本次修复**不动安全策略一行**，只补「用户下一步该点哪」。

## 三、改动（commit 内容）

| 文件 | 改动 |
|---|---|
| `check.html` | ③④ 两个面板各加一个空容器 `#local-only-hint` / `#local-only-hint-edit`；引用版本号 `?v=20261019 → ?v=20261026`（防浏览器吃旧缓存）；页脚补一句「想在公网完成写入请用本机版」 |
| `js/check.js` | 新增 `LOCAL_HINT` 常量与 `renderLocalOnlyHint(elId, kind)`：公网时渲染一条可展开的告知条——「当前是公网版本：这一段只能看，不能写」+ 一个按钮「在哪打开本机版？」→ 展开三步说明（双击 `打开网页.bat` → 地址变 `localhost` → 刷新本页）；本机时该容器清空，界面与之前完全一致。同时在 `renderWrite()` / `renderEditBox()` 的公网分支里补了一句行动指引（**要写数据 / 要改删，请按上面那条按钮的说明在本机打开**），并把标题措辞从「写入测试只在 localhost 下开启」改为「在公网只做展示：不出现输入框，也没有写入按钮」——先描述用户看到的现象，再说原因 |
