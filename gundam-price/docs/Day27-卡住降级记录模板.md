# Day 27｜卡住降级：自己试 + 记录模板

> 什么时候用这个：**真人试用者今天联系不上、或迟迟没交记录**，主任务快超时了才启用降级。真人优先，降级只是保底。

## 一、启用条件

- 已发出试用脚本，等满 **4 小时**（发链接时记一下时间）仍无进展记录；或对方明确说今天没空。
- 才做下面的降级流程。不要因为对方 20 分钟没回就自己来——那样测不出外行视角。

## 二、降级流程（自己来，但要假装第一次见）

1. 定一个 10 分钟后的闹钟，期间**不打开**项目相关任何页面。
2. 闹钟响后，打开公网链接 https://gundam-market-d7gnjqg3h1f2f156f-1499380808.tcloudbaseapp.com ，照 `Day27-试用任务脚本.md` 第 1~7 步完整走一遍。
3. 走的时候执行两条铁律：
   - **只做脚本里写的动作**，不靠记忆抄近道（你脑子里的地图试用者没有）。
   - 每一步按下表问自己：**如果我从来没见过这个页面，我知道下一步点哪吗？** 不知道就停，抄下当时屏幕上的样子，再继续。

## 三、降级记录表（找到第一个「找不到/不理解」就填完，然后可以停）

| 项 | 内容 |
|---|---|
| 第一个卡点 | 第 ___ 步，具体位置（页面 + 按钮/文案）： |
| 当时屏幕显示 | （抄页面上的字，或截图贴进来） |
| 卡的原因猜想 | 文案含糊 / 入口不显眼 / 要先懂概念才能懂 / 其他： |
| 后续步骤是否完成 | 是 / 否（走到哪停：） |
| 模拟原话 | 用「一个完全不懂的用户」的口吻写一句当时会嘟囔的话，例：「这堆字里哪个能点？」 |

## 四、降级结果的用法

- 降级记录**算今天的试用素材**，填进 `Day27-试用记录表模板.md` 第三节的统计里，试用者称呼写「Master(降级)」。
- 卡点照样走 `Day27-卡点优先级与修复模板.md` 的筛选和修复流程。
- 但完成标准里「一位真人完成核心流程」这一项**不因降级打勾**——明天补邀一位真人，或如实记录为未达成。
