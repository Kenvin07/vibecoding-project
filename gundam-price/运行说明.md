# 运行说明 ｜「高达行情」MVP（Day 10 更新）

> 本文件记录怎么把这个网页跑起来、怎么更新数据、出错了怎么排查。

## 一、启动（每天看行情时就跑这一遍）

1. 按 `Win` 键，输入 `cmd`，回车，打开命令行窗口
2. 依次输入下面两行（每行回车）：

   ```
   cd C:\Users\13546\Desktop\vibecoding打卡project\gundam-price
   python -m http.server 8000
   ```

3. 看到 `Serving HTTP on :: port 8000` 就是启动成功；这个窗口开着 = 服务器开着，关掉窗口 = 服务器停了
4. 浏览器打开：`http://localhost:8000`
   - 首页：`http://localhost:8000`
   - 五算计算器：`http://localhost:8000/calc.html`
5. 强制刷新（数据改完没变化时用）：`Ctrl + Shift + R`（笔记本键盘若 F5 被占用，用这组即可）

## 二、手机上看（可选）

手机和电脑连**同一个 WiFi**，手机浏览器输入 `http://电脑IP:8000`
（电脑 IP 查法：命令行输入 `ipconfig`，找「IPv4 地址」，形如 192.168.x.x）

## 三、每天更新价格（数据录入）

1. 用记事本打开 `data/data.json`（右键 → 打开方式 → 记事本）
2. 改各渠道的 `price`（数字，不要引号）；暂无报价保持 `null`
3. 把顶部 `"updatedAt"` 改成今天的日期
4. **Day 10 新增：** 在该机体的 `"history"` 数组里**追加一行当天最低价**（三渠道里最小的那个数）：
   `{ "date": "2026-09-26", "price": 225 }`
   ——前一行结尾要补逗号；日期用引号、价格不用。追加的每一天都会变成详情页走势图上的一个点
5. 有购买链接就填 `url`，没有保持 `""`
6. 保存（`Ctrl+S`）→ 浏览器 `Ctrl + Shift + R` 刷新即可见新数据

## 四、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面显示红色「数据加载失败」 | data.json 格式错（多逗号/漏引号）或服务器没开 | 检查刚改的地方；确认命令行窗口还开着 |
| 双击 index.html 打不开数据 | 浏览器禁止 file:// 页面读本地文件 | 必须按第一节用本地服务器，不能双击 |
| 改了数据页面没变 | 浏览器缓存 | `Ctrl + Shift + R` 强制刷新 |
| `python 不是内部或外部命令` | Python 不在 PATH | 告诉 AI，换 VS Code Live Server 方案 |

## 六、可复用组件怎么用（Day 8 加练项）

把「一台机体长什么样」收进了 `js/components/kit-card.js`，以后加新页面只要引一次脚本、调一个方法，不用复制粘贴卡片代码。

**引法（顺序不能反，组件必须先引）：**

```html
<script src="js/components/kit-card.js"></script>
<script src="js/main.js"></script>
```

**方法速查：**

| 方法 | 用途 |
|---|---|
| `KitCard.renderList(容器, 机体数组, { rate: 汇率 })` | 成功态：渲染一整列卡片（Day 10 起底部为价格对比条：最低现价 vs 五算基准） |
| `KitCard.renderSkeleton(容器, 3)` | 加载态：渲染骨架占位卡片 |
| `KitCard.create(单台机体, { rate, onOpen })` | 只想渲染一张卡片时用，返回 DOM 节点 |
| `KitCard.priceRange([价格数组])` | 算出「¥230 ~ ¥300」这种价格区间文案 |
| `KitCard.validPrices(机体)` | 挑出有效价格（过滤掉 null 的暂无报价） |
| `KitCard.fiveKBase(官方日元价, 汇率)` | 五算基准价 |
| `KitCard.tierOf(最低现价, 五算基准)` | 行情档位：捡漏 / 合理 / 溢价 |
| `KitCard.historySeries(机体, 天数=30)` | 近 30 天历史价序列（升序、过滤坏数据，Day 10 新增） |
| `KitCard.historyMin(机体, 天数=30)` | 近 30 天最低那条 `{ date, price }`，无历史返回 null（Day 10 新增） |
| `KitCard.PLATFORM_NAMES` | 渠道代号 → 中文名（pdd / taobao / xianyu） |

**示例：以后 Day 9 加个新页面，想显示同样风格的卡片列表，只要：**

```html
<div id="my-list"></div>
<script src="js/components/kit-card.js"></script>
<script>
  fetch("data/data.json").then(r => r.json()).then(data => {
    KitCard.renderList(
      document.getElementById("my-list"),
      data.kits,
      { rate: data.meta.exchangeRate }
    );
  });
</script>
```

> 注意：组件里的标识符一律用英文（如 `fiveKBase`）。中文方法名曾经踩过坑——`准`(U+51C6) 和 `準`(U+6E96) 两个码位肉眼看不出区别，但会让调用直接报 `is not a function`。所以代码里的名字坚持用英文，中文只出现在注释和页面上。

## 七、发布前检查（Day 25 新增）

**一句话：提交或部署之前先跑这一条，全绿才发。**

```bash
# 在仓库根目录（vibecoding打卡project）执行
bash gundam-price/scripts/verify-project.sh

# 没网 / 不想碰公网时，只跑静态项
bash gundam-price/scripts/verify-project.sh --offline
```

它会跑 16 项检查，逐项打印 `PASS / FAIL / SKIP` 和证据（命中几条、返回什么、哪一行）：

| 类别 | 查什么 |
|---|---|
| 密钥与配置 | 代码里有没有密钥真值、`.env` 有没有混进仓库、Git 历史里有没有提交过密钥、云函数环境变量清单是否完整 |
| 前端 | 四个页面的 `?v=` 版本号是否一致、是否落后于代码改动、引用的 js/css 是否都存在 |
| 后端与数据 | 未登记路径的兜底是不是还在、软删除与防重复索引是否完整、用户文案有没有漏技术术语 |
| 公网 | 健康接口、三条读接口与数据基线、`/api/nope` 是否返回本项目外壳 404、跨域白名单、写接口无密钥是否 401、单条路径方法白名单 |

**输出怎么看**：`PASS` 才能发；`FAIL` 先修（一次只改一处，改完从头重跑）；`SKIP` 代表这项没验证，不能当全绿。
脚本退出码：`0` 无 FAIL，`1` 有 FAIL，`2` 环境不对。

**检查项的判据和来历**写在 `skills/verify-project/SKILL.md`（每一项都注明是哪个 Bug 换来的，别凭感觉改）。
**误报豁免**只允许写在 `skills/verify-project/allowlist.txt`，且必须是文档里的示例值 —— 真值永远只放云函数环境变量。

> 典型用途：换电脑、重建 CloudBase 环境之后先跑一次。有几项配置（`/api` 兜底路由、跨域白名单、环境变量）**只存在控制台、不在 Git 里**，跑一次就能知道有没有漏配。

## 八、发布与回滚（Day 26 新增）

**一句话：发布 = 传一个打包好的文件夹；回滚 = 传回上一个文件夹。不碰代码。**

```bash
# 1) 打发布包（只含前端资源，自动写 version.json）
bash gundam-price/scripts/make-release.sh 1.0.0

# 2) 上传 gundam-price/releases/v1.0.0/ 到静态托管根目录（控制台操作）

# 3) 核验：首页 / 版本号 / 接口四项
bash gundam-price/scripts/check-live.sh

# 4) 要回滚时：先挂这条命令，再上传上一版的文件夹，它会自动报耗时
bash gundam-price/scripts/check-live.sh --wait-for 0.9.0
```
